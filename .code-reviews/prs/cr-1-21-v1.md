## Important Issues

### 1. Fragile String Replacement in Import Removal

**Location:** `Catan3.Shared/TypeScript/TypeGenRunner/Program.cs:391`
**Severity:** Important

The `RemoveUnusedImports` method relies on exact string replacement including line endings:

```csharp
content = content.Replace(importLine + "\r\n", "");
content = content.Replace(importLine + "\n", "");
```

This approach is brittle:

1. It fails if the import is the last line of the file (no trailing newline).
2. It fails if there is unexpected whitespace (e.g., trailing spaces).
3. It keeps the line if the file uses mixed line endings not matching the hardcoded strings.

**Recommendation:**
Use `Regex.Replace` to match the line and its newline terminator robustly.

```csharp
// Replace the import line and any following newline
var linePattern = Regex.Escape(importLine) + @"\s*\r?\n?";
content = Regex.Replace(content, linePattern, "", RegexOptions.Multiline);
```

### 2. Regex Sensitivity to Comments

**Location:** `Catan3.Shared/TypeScript/TypeGenRunner/Program.cs:309`
**Severity:** Important

The regex for matching properties expects the line to end immediately after the semicolon:

```csharp
var pattern = $@"^\s*{camelPropName}:.*?;\r?\n";
```

If TypeGen (or a future update/configuration) adds inline comments (e.g., `prop: string; // comment`), this regex will fail to match, and the `[JsonIgnore]` property will remain in the file.

**Recommendation:**
Allow for optional trailing characters (whitespace/comments) before the newline.

```csharp
// Allow whitespace or comments after the semicolon
var pattern = $@"^\s*{camelPropName}:.*?;.*?\r?\n";
```

### 3. Hardcoded Values in Inspection Script

**Location:** `react-ui/inspect-recording.mjs:2`
**Severity:** Important

The script contains hardcoded values that limit its utility and could cause confusion:

```javascript
const recordingId = 'eeb91a91-6597-4360-89d5-e3d55cbc7839';
const response = await fetch(`http://localhost:8080/api/recording/${recordingId}`);
```

It requires the GameService to be running on port 8080 and a specific recording to exist.

**Recommendation:**
Use `process.argv` to accept the recording ID and optional base URL as command-line arguments, with the current values as defaults if needed.

## Suggestions

### 1. Robustness of Type Usage Detection

**Location:** `Catan3.Shared/TypeScript/TypeGenRunner/Program.cs:405`
**Severity:** Suggestion

The type usage check might generate false positives if the type name appears inside a string literal:

```csharp
var typeUsagePattern = $@"\b{importedType}\b";
```

If the code contains `console.log("Warning: Check HexCoordinates")`, it will count as a usage of `HexCoordinates`. While unlikely to break the build (it just leaves an unused import), it's worth noting.
